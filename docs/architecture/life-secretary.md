# 生活秘书：我的待办与今日规划

生活秘书负责收集、整理生活中需要处理的事情，结合截止日、固定安排与可用时间提出规划。侧栏只有一个「生活秘书」入口；页面内的「今日规划」「我的待办」共用 `tasks` 数据和独立的 `life` Agent 会话。

## 页面与事项

- `tasks` 页签为「我的待办」：快速记录、筛选、查看原话、补充信息、完成与安排。旧待办和需求导入仍可在这里找到。
- `today` 页签为「今日规划」：按日期查看固定与灵活事项，安排待办、改期、取消安排、完成事项。
- 以 Web 为设计与验收目标。进入「生活秘书」默认显示「今日规划」，上方可切换「我的待办」；事项与秘书对话并列。页签切换不卸载秘书会话或丢失输入草稿。刷新后沿用模块 Agent 的会话恢复机制。
- 需求导入、主页和知识来源里的待办链接进入生活秘书的「我的待办」页签，并保留来源筛选。内部切换页签时清除该筛选，以免把普通待办视图限定在一条需求。
- 新增事项默认没有截止日或计划日。`due` 表示最晚何时完成，`plannedDate` 表示准备何时处理；两者独立。
- `originalText` 保留原话，`note` 记录补充内容，`durationMinutes` 表示预计耗时，`kind` 区分固定/灵活事项，`startTime/endTime` 表示具体时间段。
- 取消安排只清除计划日期与时段。未完成的旧安排保留，可以重新安排；完成状态始终是同一个 `tasks.done`。

## 秘书能力与确认

`config/agents/life.yaml` 和 `prompts/life.md` 统一维护身份、提示词、模型与工具白名单。生活秘书拥有独立会话、工作目录和知识绑定，复用模块 Agent 的 SDK 装配机制。

- `life_context` 读取本地日期、时区、事项与已有安排。
- `life_capture` 保存结构化事项与原话，以会话和条目标识支持幂等重试；不擅自安排日期。
- `life_propose_plan` 保存 `lifePlans` 草稿；任务此时尚未排期。
- 页面展示本会话方案，用户点击确认后请求 `POST /api/workbench/life/plans/:id/apply`。服务端核对草稿及任务版本，在事务内验证并应用整批排期；过期、冲突或任一条失败时不部分保存。
- 草稿确认不修改截止日期；重复确认不重复创建事项。固定时间应得到保护，调整固定安排使用明确的手动操作。

秘书应先记录已知信息，只询问影响安排的缺失信息，考虑交通、休息与余量。日期安排不等于向外部完成预约、发消息或设置后台提醒。重复事项、定时提醒、日历同步不在本次实现范围。
