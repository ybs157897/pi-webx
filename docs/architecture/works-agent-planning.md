# 工作助理 Agent 与工作排期

工作助理现在默认打开独立的规划对话和工作时间表。通过对话说明工作内容、截止时间和可用时段，助手读取真实待办与已有安排后规划；用户明确要求安排或同意具体方案时，保存日期与起止时刻。

## 功能与配置

- 桌面同时显示对话和工作安排；窄屏切换「对话规划 / 查看安排」。
- 工作安排按日期、开始时间排序，未排期事项独立显示；可标记完成、查看已完成、点击标题手动改期。
- 原有看板和列表保留在「工作清单」，手动编辑增加工作日期、开始时间、结束时间和清除排期。
- 配置：`config/agents/works.yaml`；提示词：`config/agents/prompts/works.md`。Agent 配置页可分别编辑提示词、模型、Skills 与工作目录。
- 会话恢复指针、配置快照、工作目录与知识库沿用公共隔离机制，身份为 `works`。

## 数据与工具边界

- `works_context` 返回服务器本地日期、时区、未完成待办、工作与排期；支持检索、限制条数和 offset 翻页，明确返回数量和截断信息。
- `works_schedule` 批量新增或修改工作，字段为 `scheduledDate`（YYYY-MM-DD）、`startTime` / `endTime`（HH:mm）。只建立对已有待办的引用，不改待办状态或截止日。
- 日期与起止时刻必须同时填写；结束晚于开始。跨天工作分成独立时段。
- 未完成工作不能重叠；已完成记录保留历史时间，不占用当前规划的可用时段。HTTP 写入、整库导入和 Agent 调用都执行排期校验。
- 同批排期先校验最终状态，再在同一 SQLite 事务写入。改期支持同批交换时段，不会被中间状态误判为冲突。
- `(sessionId, entryKey)` 固定绑定工作记录，重试不重复新建。修改必须携带 `expectedUpdatedAt`，过期内容返回冲突；不存在的 id 不会被当成新建。
- 助手只安排工作，不承诺定时提醒或后台执行。

## 可重复浏览器验收

运行 `npm run dev:works-fixture`，默认 API 为 `127.0.0.1:18879`。另以 `PI_WEBX_PORT=18879 npm run dev:web -- --port 15174 --strictPort` 启动前端。

夹具使用独立临时数据库、配置和会话，禁止模型联网。可以用 `PI_WEBX_WORKS_FIXTURE_DIR` 指定隔离目录、`PI_WEBX_WORKS_FIXTURE_PORT` 指定端口；同一目录可用于重启恢复。第二轮输入明确日期和两段各至少一小时的可用时间。夹具会在每段内排一小时；测试结束后停止进程并清理其临时目录。
