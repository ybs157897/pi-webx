# 需求对话与待办导入

需求菜单默认打开主区域中央的需求助手。对话使用独立的 requirements Agent；原有需求列表、阅读和编辑保留在「需求记录」。

## 用户流程

1. 描述想法，或粘贴已有需求；助手逐步澄清目标、范围、约束和验收条件。
2. 信息足够后，助手保存需求正文和结构化待办草稿。保存草稿不创建待办。
3. 对话下方自动显示本会话的草稿。点击「预览并导入待办」可阅读需求、编辑标题/优先级/日期/标签、增减或取消条目。
4. 确认后整批导入我的助理的「待办」页签，并切到全部日期、该需求来源的筛选视图。可清除来源筛选查看全部待办；只有明确安排日期后才出现在「今天」页签。
5. 待办来源按钮回到对应需求记录。已导入需求显示「查看待办」，不重复生成任务。旧需求也可从记录页手动拆分导入。

## 实现边界

- 会话、配置、提示词沿用模块 Agent 装配机制，配置仍在 `config/agents/requirements.yaml`。
- `requirements_save_draft` 由 SDK 上下文注入 `sourceSessionId`，不能修改其它会话的草稿；普通记录 POST/PATCH 不接受客户端指定来源会话。
- `taskDrafts` 是最多 20 项的结构化数组，不从 Markdown 猜测或解析待办。
- `POST /api/workbench/requirements/:id/import-tasks` 接受 `{ expectedUpdatedAt, tasks? }`。过期预览返回 409；同一 SQLite 事务创建任务、写 `refs` 来源并保存 `importedAt` / `importedTaskIds`。
- 重复提交同批内容返回已有结果；已导入后不能以不同草稿再次导入。任务与需求的导入标记在重启及全库导出导入后保留。
- `updatedAt` 保持单调，以识别同一毫秒发生的修订。部分任务写入失败时整批回滚。
- 保存成功但刷新列表失败时，弹窗明确提示已经保存并锁定条目；「重新加载待办」只重试读取。
- 需求对话是页面中的 region，导航保持可用；导入预览是模态对话框，提供初始焦点、Tab 圈定、Esc 和焦点恢复。

## 群聊交接入口

普通页面保留上述草稿预览导入流程。用户也可在「内部聊天室」直接 `@需求管理` 说明要做的需求；需求 Agent 澄清后用 `requirements_dispatch` 原子保存需求并加入待办，再 `@代码开发` 实施，开发完成后 `@我的助理` 更新状态。普通页面已经保存的草稿可携带 ID 与版本交给群内需求会话复用。该入口的 @、回复、幂等与范围校验见 [内部聊天室](internal-chatroom.md)。
