# 需求根与执行身份分别保存

Status: implemented

## 决策与理由
以首次保存的 requirementId 为根，内容修订与时间戳分开。通用 SQL 日志覆盖直接业务写入，正式执行与交付通过可信源关联。输入版本不可漂移；来源时间未知时明确标记。参见 [完整协议](../../../docs/architecture/requirement-lifecycle-tracing.md)。

## 放弃了什么
不把 session/thread/run 当生命周期根，不只在工具调用后写日志，不把所有记录修改（如星标）都当内容修订，也不把任务完成或证据提交当人工接受。同话题新需求保留分叉因果，不重写旧输入归属。

## 复活条件
需要多宿主协调或独立审计留存时，再增加跨进程租约/独立权限和存储；本次同宿主 SQLite 事务不是外部工具 exactly-once 或独立多租户审计系统。
