# 图片输入、工具结果与模型弹窗补齐

Status: implemented

## 决策与理由

图片输入沿用 Harness 的 64px 缩略图、16px 圆角、移除按钮、原图弹层和文件拖放交互。浏览器不再只保留前四张；输入、历史和服务端共享 20 张/单图 20MiB 的准入约束。发送仍走 pi SDK 的原生 image content，服务端在入队之前规范化并持久化；历史里保留同一份规范化数据。不支持图片的模型明确拒绝，避免收到文字却漏掉图片。

模型弹窗按参考图保留独立滚动正文与固定首尾，保留模型 ID 编辑，去掉参考中没有的显示名称项，删除移至模型列表。保存保留未显示的原生配置及原有推理等级映射目标。供应商取消操作重建原始草稿，防止下次打开继续显示已取消的改动。JSONata 映射、视频/PDF 和扩展能力仍是已有记录字段，其运行时边界保留在提示中。

write/edit 展开区显示实际工具输出，统一使用限高滚动容器。取消根据请求参数重建 diff：它是输入，失败或尚未完成时不能据此宣称文件已经改变。

## 放弃了什么

没有引入另一套 DSH 执行引擎；pi 的图文消息、历史及排队链路继续是运行时事实来源。没有照搬 Harness 的 200MiB 总量：本项目目前使用内联 base64 请求，所以保留已验证的 24MiB 消息总量上限，并在前端明确提示，整批拒绝超限输入而不静默截断。

## 复活条件

若需要单条消息超过 24MiB 的原图，先把上传改为独立附件接口、prompt 仅携带引用，再提升总量；同时覆盖上传失败、引用丢失、排队和重启后读取的验收。
