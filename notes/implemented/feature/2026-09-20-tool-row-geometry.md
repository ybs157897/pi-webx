# 工具行按 dsh 的行几何重画

Status: implemented

## 决策与理由

工具行（图标 · 标题 · 摘要）原先按本应用自己的样式画：标题与摘要都用**等宽代码字体**、
分隔符是一个 `·` 字符（`opacity: 0.45`）。现在按 dsh 的 figma 行（`122:9479`）重画：

| | 之前 | 现在（= dsh） |
| --- | --- | --- |
| 标题 | 主色 + 等宽字体 | `label-secondary`、body 字体、13/24、400 字重 |
| 分隔符 | `·` 字符 | 2×2 圆点、`border-radius: 1px`、`label-caption`、两侧 8px |
| 摘要 | secondary + 等宽字体 | `label-tertiary`、body 字体、填充截断 |
| 失败行摘要 | 命令/路径，染红 | 失败**首行**替换摘要（`failureLine ?? summary`），染红 |

这是**共用行**：read / edit / grep 等所有工具行一起变，不只 bash。

## 放弃了什么

- **保留等宽字体的工具名。** 等宽在没有终端卡的那些行上是本应用旧有的辨识度来源。放弃的
  理由是行属于界面层而不是载荷：参数、命令、输出这些**要被读成文本**的东西在展开体里，仍然
  是等宽的；标题和摘要是一行界面文案，参考实现对它们用正文字体。两者字号一致（13px），所以
  变的是字面而不是节奏。
- **给 bash 单独定制这一行。** 让共用行按工具分叉会立刻产生第二套行几何，而参考实现里行
  几何是共用的——bash 与 read 的差别在展开体，不在行。
- **保留「失败行仍显示命令」。** 那会让一行同时说两件事（跑什么 + 哪里坏了），而命令在展开
  的终端卡里就在下一行。失败首行是参考实现让这一行唯一要说的东西。

## 复活条件

- **如果 pi 开始提供工具调用的 `description`**（行摘要能放一句人话）：失败行不应再无条件让位
  给失败首行，届时按参考实现的优先级 `failureLine ?? description ?? summary` 重排。
